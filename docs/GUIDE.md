# 运维指南

从 README 移出的运维细节与行为说明。协议格式与架构决策见 `docs/adr/`。

## 认证密钥

- 服务端首次初始化数据库时插入固定初始密钥 `2nC7NBBcutpkJg0cPkyQgkzXqtWrri/JB4QyXI5N258=`，范围为 `default:*`（default 分组全部客户端）；示例客户端配置使用同一密钥。后续重启不会重复插入、覆盖修改或恢复已删除的密钥；已有配置或密钥的数据库不会补入该默认值。
- 密钥表非空时只使用表内密钥及其范围授权，配置文件里的 `server.auth.key` 不生效。清空密钥表后，可执行 `./vnserver keygen` 生成密钥填入两端作为回退；密钥为 32 字节随机数的标准 Base64，没有可用密钥时拒绝客户端连接。
- 密钥范围支持 `*`（全部客户端）、`office:*`（office 分组）、`office:desktop-01`（单个客户端）；`server:self` 保留给服务端本机出口。管理台添加接口不接受手工指定密钥。
- 密钥在服务端启动时建立内存索引（握手查找与范围授权平均 O(1)）；管理台增删即时更新索引。绕过管理台直接改库、或多服务端共用数据库时，需要重启相关服务端同步。
- **升级（BREAKING）**：服务端与内网客户端必须同步升级，旧明文客户端、旧短口令与旧密钥 API 不再支持。升级后先在新管理台生成密钥更新客户端，再删除旧密钥；数据库不自动改写。删除密钥立即拒绝新连接，已建立会话在下次配置上报时重新校验，可在客户端列表主动断开。

## 客户端身份（group / name）

- 客户端配置分别设置 `group` 与 `name`，上报为两个独立 JSON 字段；服务端内部绑定键为 `group:name`（如 `office:desktop-01`）。
- `group` 留空用 `default`；`name` 留空生成 `<hostname>-<IPv4>`（取不到 IPv4 则省略后缀）。两项都不能包含 `:` 或 `*`。
- **名称升级（BREAKING）**：已取消 namespace，旧 `namespace:group:name` 不再接受，两端需同步升级。旧三段式密钥范围需改为两段（`X:*` 现在表示分组 X），可在管理台重新生成密钥；不同 namespace 下的同名客户端合并分组前需先消除重名，数据库不自动改写。

## 加密传输

- 管理台「服务配置 → 加密传输」控制握手后的隧道加密，默认开启：TCP 与多路复用之间使用 ChaCha20-Poly1305 AEAD，覆盖配置上报、心跳、配置与隧道数据。关闭时明文传输。
- 两种模式都验证 `auth_key` 并执行范围授权；握手使用双方随机挑战、HKDF-SHA256 与 HMAC-SHA256 双向证明，只传输公开 key_id，不发送原始 PSK。PSK 不提供前向保密，同一密钥持有者属于同一信任范围。
- 开关只覆盖 vnray 内网隧道：VLESS / VMess / SS 入站与管理台 HTTP 各自独立。开关落库，新连接生效，在线连接重连后生效；客户端自动跟随，无需配置。
- 客户端与服务端必须同步升级后才能启用该开关（握手版本 v2 与旧 AEAD v1 不兼容）。

## vnray-user 用户入站

- `vn-v1` 用户通过独立端口连接（管理台插件页配置并启用，默认停用），内网客户端继续走原主端口；主端口不再接受用户连接。
- 插件端口可在运行中热切换：先准备新监听，失败时保留旧监听与既有连接；进程退出会关闭并等待存量连接。会话参数热改对新连接生效。

## 客户端配置下发（Host / IP 映射）

- 管理台「客户端配置」页统一设置自定义域名映射（如 `youyuevpn4.route → 192.168.60.1`）与 IP 段映射（如 `186.12.12.* → 192.168.60.*`），保存后立即下发给在线客户端，离线客户端下次连接时获取，重启后保留。
- 服务端通过 `client_config` 与 `global_config` 两层下发：客户端先查独立配置，未命中查全局；IP 映射每层取首条命中，独立规则即使映射为自身也不再查全局。全局配置不作用于 `server:self` 本机出口。
- 域名需要由代理请求传入 vnray；浏览器把单段名称当搜索词或提前本地解析时，这里的映射不会参与。
- 客户端编辑页只显示独立配置，删除独立规则即恢复全局；清空全局并保存只撤回全局值，不删除客户端独立配置。

## 日志页

- 首次显示文件末尾最多 300 行，随后实时追加，页面保留最近 1000 行（约 256 Ki 字符）；「清空页面」只清当前页面，不改服务端文件，重新打开会重新读取末尾。
- 日志需写入 `log.output` 指定的文件；经反向代理时请允许 `/admin/ops/api/logs/stream` 持续传输并关闭响应缓冲。

## 监控

- 「监控」页分为「用户监控」与「主机监控」两个 tab。旧指标地址跳转到主机 tab。
- 用户监控默认以列表展示每位用户的最新 TCP 连接数、stream 数、累计代理请求、上下行速率及累计字节。切换多宫格后，每个用户一张折线图；右上角可放大为弹窗，支持图例开关和时间缩放。
- TCP 为已认证物理入站连接，stream 为当前逻辑流（普通代理连接计一条，mux 按子流计）。请求为代理目标请求，含拒绝与失败，不含心跳，也不解析隧道内部 HTTP。上下行统计成功写出的载荷；监控累计值从服务进程启动起计，与用户页跨重启累计账务流量不同。
- 在「服务端配置 → 其他 → 性能监控」开启采集，并设置采样间隔与历史保留时间。默认 `2s` / `1h`；间隔允许 `1s`–`1h`，保留时间至少一个间隔、最多 `168h`，最多保留 10000 个采样周期。设置持久化且自动生效。
- 历史保存在现有数据库，跨刷新和重启保留，过期自动删除；关闭采集时仍清理历史。曲线在选定时间范围内最多均匀选取 120 点，较短尖峰可能在降采样时被跳过。删除用户后不再展示其历史。
- 主机指标 API 只读已编码缓存；用户历史 API 读取有界样本，不在请求上执行系统或 Go runtime 采样。
- 采样由独立监控模块运行，不依赖打开管理台；最新用户列表不查历史数据库，只有曲线按需加载历史并按采样批次缓存。目录在用户变更后重新加载，平时只读取共享原子计数器。数据库过期清理每分钟执行，查询会立即过滤超出保留期限的数据。
- 服务器：CPU、内存与非回环网卡速率（Linux / OpenWrt 完整支持，口径为 OS 可见资源）；进程：CPU 时间差、RSS、Go 堆、GC；运行：缓冲待消费字节、握手、在途请求与上下行载荷。
- 关闭后暂停采样但状态量继续配对更新；首次速率未就绪或平台不支持显示 `—`。macOS 仅支持进程 CPU、主机内存与 Go runtime。

## 存储与初始化

- 数据库启动时先建表，再在单个事务内写入初始密钥、服务配置、默认规则与插件初始状态，任一失败即回滚并阻止启动；已有数据库保留已修改记录，旧版初始化标记与规则键同事务迁移。
- 初始化完成后，修改配置文件的 `plugin.enabled` 不再补写插件记录，后续启停请使用管理台。MySQL 建表语句不参与事务但可重复执行。

## 界面语言

管理台支持中文与英文：顶栏按钮即时切换，首次按浏览器语言选择，之后记住选择（`localStorage` 的 `vnray.locale`）；接口提示文案跟随 `Accept-Language` 协商，未声明时回落中文。
