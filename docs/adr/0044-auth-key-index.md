# 0044 — 按 key_id 索引客户端密钥

状态：已采纳

Supersedes: [0043](0043-client-aead-transport.md) 实现中每次握手及范围授权全表读取认证密钥的查询方式。线协议、密钥派生和既存会话的撤销语义不变。

## 决策

- 服务端装配时加载一次密钥表，建立 `key_id → 已解析密钥、授权范围` 索引。加载失败使启动失败。独立构造 Bindings 的调用方允许首次访问时加载，多个并发冷查询只执行一次成功加载。
- 握手按 key_id 点查，范围授权按提交密钥计算 key_id 后点查，只匹配该条记录。热路径不访问数据库、不遍历密钥；相对于密钥数量，平均 O(1)。首次加载、显式重载和管理台列表仍为 O(n)。
- 索引由 RWMutex 保护。增删和范围更新串行执行：先持久化、再原地更新索引，成功返回后后续查询立即看到修改。普通更新不复制或重新扫描整张表。
- 保留全部原始行的存在性索引，包括无法用于 AEAD 的旧密钥；旧行不能被认证，但仍禁止回退到配置文件密钥。删除最后一行后才恢复配置文件回退。
- 写入失败可能意味着数据库已经提交但响应丢失，必须使内存索引失效。后续查询重新加载，读取失败时拒绝认证及配置文件回退。显式重载失败也不能继续使用旧索引；数据库恢复后可重新加载。
- 已成功加载且没有失效的索引不依赖数据库在线性；单纯的数据库暂时不可用不会主动撤销缓存权限。
- 管理台经 Bindings 写入同步更新本进程索引。不承诺发现绕过 Bindings 的直接 SQL 修改，也不提供多个服务端进程的缓存广播。此类修改需要重启相关服务端，或由程序调用 ReloadAuthKeys；不新增面向网络的重载接口。

## 验证

覆盖万条密钥命中和未命中时零额外数据库查询、范围热更新、最后一条删除、旧密钥行、并发冷加载/读写、失败重载与恢复，以及提交结果不确定后的拒绝行为。基准测试比较 1、1000、10000 条密钥的握手查询与范围授权开销。
