# ADR 0062：客户端身份仅保留分组

- 状态：已采纳
- 日期：2026-11-11
- Supersedes：原客户端 `namespace:group:name` 命名与按 namespace 授权的约定。

## 背景

客户端原有 namespace 和 group 两层分类，生成接入密钥时却仅支持 namespace 范围。统一为一层分组，使客户端名称和密钥授权范围使用同一概念。

## 决策

- 客户端名使用 `group:name`，恰好两段，每段非空且不能包含 `*`；客户端配置和服务端首次、后续配置上报都校验格式。
- 未配置 name 时生成 `default:<hostname>-<IPv4>`；取不到 IPv4 时省略后缀。网卡选择、进程内固定名称及重连行为不变。
- 接入密钥范围仅允许 `*`、`group:*` 和 `group:name`，分别匹配全部客户端、一个分组和一个客户端。非法名称不能命中任何范围。
- `server:self` 继续保留给服务端本机出口，由服务端显式拒绝远程客户端占用。
- 管理台和 OpenWrt 配置页同步使用两段名称与分组授权提示。密钥的生成算法、编码、握手及消息类型编号不变。

## 兼容性与迁移

这是身份与授权语义的 BREAKING 变更，客户端与服务端需同步升级。旧三段名称不会被自动截断；不同 namespace 下相同的 group/name 合并后可能重名，必须由管理员选择唯一的新名称。

升级时同步修改显式客户端名、用户绑定、端口映射、客户端专属配置及精确密钥范围。默认生成名称的客户端也会从 `default:default:<实例名>` 改为 `default:<实例名>`。

已有 `*` 范围继续适用；已有 `X:*` 的文字值保持不变，但含义改为分组 X，需核对是否符合预期。旧三段精确范围不再匹配新名称，可重新生成相应范围的密钥并更新客户端。程序不改写现有数据库记录。

## 验证

覆盖两段名称与非法输入、默认名称、三类密钥范围、跨分组拒绝、旧名称拒绝、本机保留名、密钥生成 API、配置上报和前端构建；执行全项目 race、vet、依赖边界及 transport 重复测试。
