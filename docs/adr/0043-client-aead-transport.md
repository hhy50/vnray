# 0043 — 内网客户端使用 auth_key 建立 AEAD 传输

状态：已采纳

Supersedes: 此前客户端直接在明文 TCP 上建立 yamux、共享口令为空时放行的传输与认证决策。历史 ADR 文件不在当前副本中，不虚构编号；既有 ADR 不删除。

## 背景

客户端到服务端的控制帧与隧道数据需要统一保密和完整性保护。采用用户选定的 PSK + AEAD 方案，并复用 auth_key；密钥创建不再允许人工输入。

## 决策

- auth_key 为系统随机源生成的 32 字节密钥，以规范标准 Base64 表示。管理台 POST /api/keys 只接受范围，服务端生成并保存密钥；vnserver keygen 支持无管理台部署。
- 在 TCP 与 yamux 之间增加 internal/secure 字节流包装，固定使用 ChaCha20-Poly1305。标准密码原语使用现有 x/crypto 依赖，不增加运行时依赖。
- 使用双方各 32 字节随机挑战、HKDF-SHA256 和角色区分的 HMAC-SHA256 完成 PSK 双向证明。服务端只在客户端完成新挑战的证明后创建 yamux；不允许早期业务数据。录制的客户端首包无法在新挑战下完成握手，因此不依赖时间戳、时钟同步和重放缓存。
- 公开密钥标识为带域隔离的 SHA-256 摘要，用于服务端选择密钥，不发送原始 PSK。Auth 在加密连接内继续执行范围授权，并与传输握手的密钥标识绑定，不能在 Auth 中切换密钥。
- 分块采用加密长度 + 加密载荷，明文块上限 16 KiB；两方向独立密钥与计数器。每方向每 65536 条记录自动派生下一代密钥。认证、截断或 I/O 错误永久终止连接。
- 长期密钥泄露后历史录包可被解密，此设计没有前向保密。自动换代不改变这一结论。所有持有同一 PSK 的设备均能证明服务端身份，因此细分范围应配合不同密钥。
- 保留原有 vn-v1 用户的明文 yamux 路径；此路径仅允许 UserAuth，明确拒绝客户端 Auth，不提供自动明文回退。用户密钥和客户端传输密钥不混用。VLESS/VMess/SS、管理台 HTTP 不受此传输层覆盖。
- 密钥表非空时优先于配置文件，读取失败拒绝连接。旧密钥不自动转换、不删除，不能用于新传输。删除密钥不终止既有会话，可通过管理台断开。

## 兼容性

BREAKING：服务端与内网客户端同步升级；旧口令替换为生成密钥。密钥创建 API 不再接受手工 key。DMP 帧头与全部消息编号不变，传输层独立版本号为 1。旧 vn-v1 用户工具继续兼容。
