# 0055 独立监控模块与低开销统计

Supersedes 0054 中由 Admin 拥有采样生命周期及每轮读取用户目录的方案。
指标口径、保留期限与页面交互继续沿用 0054。

## 边界

- `internal/stats`：共享原子计数器。业务仅在物理连接、逻辑流、代理请求边界记数，
  复用原有载荷字节计数，不增加每次 Read/Write 的处理。
- `internal/metrics`：全局指标原语和主机资源采样，无业务身份和数据库依赖。
- `internal/monitor`：唯一采样协程、速率计算、原子快照发布、历史查询缓存及过期调度。
  不引用 Admin、Store、配置或入站实现；依赖通过窄接口和函数注入。
- `internal/core/monitoring.go`：手写装配用户目录与 Store 适配器，绑定配置热更新。
- `admin`：认证、参数校验和 HTTP 响应，仅依赖只读查询接口。

## 性能与生命周期

用户计数器在认证或连接入口取得一次，随后经连接上下文传递；流结束以直接方法
配对回收，避免闭包及额外注册表锁。每个用户仅增加三个原子整数，零新增业务协程。
目录只在启动及用户变更后的下一轮采样读取，常规采样只读原子计数器。

最新列表与主机 API 直接复用预编码快照，O(1) 获取、无数据库查询。
仅多宫格、放大弹窗和主机历史按需查询最多 120 点；同一采样代次缓存最多八种查询、8 MiB，
过期样本到期时缓存同时失效。并发相同查询合并执行，等待可以被请求 context 取消。

数据库每个采样周期写一行，过期清理每分钟执行一次，保留时间调整会立即唤醒清理；
查询始终使用保留时间下限过滤，因此实际清理前也不返回过期数据。
持久化与查询都有超时；失败保留最新内存采样并显式报告历史未写入。
采样与历史 IO 随用户数增长，短采样周期和长保留时间仍有资源成本。

模块作为独立 Service 装配，只有一条可取消且可等待的采样协程。
关闭采样后只每分钟清理历史；配置通过唤醒信号生效，不轮询整份服务配置。
Admin 先停止，monitor 随后退出，最后关闭数据库。
