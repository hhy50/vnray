# ADR 0061：以开源环形缓冲替换管道块队列

- 状态：已采纳
- 日期：2026-11-10
- Supersedes：`internal/pipe` 原有 `[][]byte` 队列实现；沿用现有关闭语义。

## 背景

内存管道原先在每次 Write 时分配并复制一个数据块，并维护队列切片、字节总量和关闭状态。64 KiB 只检查写入前的队列大小，因此单次大写入可以突破缓冲上限。用户要求采用开源缓冲实现，减少项目维护的数据结构代码。

## 决策

引入 `github.com/smallnest/ringbuffer v0.2.1` 管理固定容量字节缓冲：

- MIT 许可证，模块仅使用标准库，无额外运行时依赖。
- Go 模块元数据记录该版本于 2026-10-26 发布，要求 Go 1.26，与项目工具链兼容。
- 支持 `io.Reader`、`io.Writer`，处理环回读写与容量计量。
- 上游源码和许可证：https://github.com/smallnest/ringbuffer/tree/v0.2.1。

仅在 `internal/pipe` 内引用库，保持 Reader、Writer、New、Close、CloseWithError 和 Interrupt 的调用接口。调用方不依赖第三方类型。

每条管道在首次非空写入时创建 64 KiB 缓冲，后续读写复用。尚未写入的管道不分配载荷缓冲。超出剩余容量的 Write 分段入队，等待读取后继续，正常返回时必须写完；关闭打断时返回已写入字节数和 `io.ErrClosedPipe`。并发的整次 Write 串行执行，避免分段后交错。

保留一个小适配层管理背压与终态，不使用库的阻塞模式、CloseWithError、WithCancel 或 Copy：库的非 EOF 关闭错误立即终止读取，而项目需要先读完缓存再返回该错误。适配层统一在同一把锁下管理缓冲访问和关闭，从而维持：

- Close：拒绝新写入，尾数据读完后返回 EOF。
- CloseWithError：拒绝新写入，尾数据读完后返回原错误。
- Interrupt：若尚未关闭，释放缓冲引用，唤醒阻塞读写并返回 `io.ErrClosedPipe`。
- 第一次关闭决定终态；后续 Interrupt 或 Close 不覆盖已经决定的尾数据与错误处理。
- 空切片 Read/Write 不等待数据或容量；关闭后的 Write 仍返回 `io.ErrClosedPipe`。

不新增生产协程或取消上下文；现有父子 ctx 的持有者仍通过 Interrupt 解除管道阻塞。

## 取舍

去掉自维护块队列、累计字节计数和状态枚举；环回与容量管理交给上游。保留项目特有的关闭契约和条件等待，避免为了完全套用库接口改变半关闭语义。

稳定传输不再为每个数据块分配内存，代价是首次写入即分配 64 KiB。仅传输少量数据的短连接会比原实现分配更多内存；这是持续传输与短连接开销之间的取舍。尚未写入的管道保持惰性分配；不引入全局池或复杂的扩缩容逻辑。

本次仅替换字节流管道；加密记录和 mux 帧编码有不同的缓冲所有权约束，不因此改动线路格式或其他模块。

## 验证

包内回归覆盖大写入背压、部分写入被关闭、中断唤醒、错误前排空尾数据、首次关闭优先、并发整次写入不交错、环回和调用方输入切片复用。使用 `testing/synctest` 验证等待状态，无固定 sleep。

`BenchmarkPipeTransfer32KiB` 衡量已初始化管道的稳态分配与搬运，`BenchmarkPipeFirstWrite` 单独暴露首次写入成本。性能数值只代表局部内存搬运，不等同于实际网络吞吐。

发布前检查包括全项目 race、pipe 的重复 race、transport 重复测试、Go vet、依赖边界和模块元数据。

本次 Windows amd64、Go 1.26.5 本机对照（每组 200 ms，重复 3 次）：稳态搬运 32 KiB 从 32,792 B/op、2 allocs/op 降至 0 B/op、0 allocs/op，耗时从 6.1–6.4 μs 降至 1.5–1.7 μs。首次写入 1 字节则从 169 B/op 增至 65,936 B/op；调用方应结合连接寿命评估这项取舍。
