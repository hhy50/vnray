## 它解决什么问题？

- 家庭宽带没有公网 IP，无法直接访问 NAS、路由器或家里的开发环境；
- 公司内网的测试 API、数据库或 SSH 服务，不应该直接暴露在公网；
- 多台机器分别能访问不同网络，想从一个公网入口统一接入；
- 只开放出站连接，不方便在防火墙或 NAT 上配置入站端口。

一般的内网穿透实现都是 **端口映射** 和 **组网**

- 端口映射，每个客户端都需要占用服务端的一个端口，并且强依赖客户端的配置
- 组网，主要是配置繁琐

### Vnray

- **Vnray的核心逻辑就是通过一个客户端，把客户端的网络环境暴露出来**
- **他的核心原理就是服务端只负责把用户的流量转发给具体的客户端，最后客户端把流量转发给目标服务**
- 从架构上来看, 它就像是在客户端装了一个v2ray服务端, 然后通过端口映射的形式, 让公网可以访问到客户端的v2ray服务端, 实际上并不是这种实现


## 工作原理

```text
┌────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────┐
│  用户  │ ─────▶ │ 公网服务端    │ ◀───── │ 内网客户端    │ ─────▶ │ 目标服务 │
└────────┘        │ 认证/路由/管理 │ 隧道    │ 访问目标网络  │        └──────────┘
                  └──────────────┘        └──────────────┘
```

| 组件 | 部署位置 | 职责 |
| --- | --- | --- |
| **服务端** | 有公网入口的机器 | 认证、路由、管理台，把用户流量按绑定关系转发 |
| **内网客户端** | 内网/目标网络 | 主动连接服务端，把请求转发到本机所在网络 |
| **用户客户端** | 用户设备 | 用 VLESS / VMess / Shadowsocks 连接服务端 |

## 核心能力

- **客户端主动建隧道**：只发起出站连接，适配 NAT 与防火墙；
- **多客户端出口**：一个服务端接多台客户端，把不同用户绑定到不同出口，支持 `server:self` 服务端本机出口；
- **VLESS / VMess / Shadowsocks 接入**：标准 v2ray / ss 客户端直接连接，mux 与 XUDP；
- **端口映射**：把客户端侧的 TCP 服务映射到公网端口，独立统计上下行流量；
- **链路加密**：客户端与服务端之间的隧道默认 ChaCha20-Poly1305 AEAD，可在管理台关闭；
- **用户出站规则**：拒绝/直连名单由服务端判定，统一作用于所有入站协议；
- **路由与 Host 映射**：客户端侧直连规则、域名到 IP 映射，服务端热更新下发；
- **带宽与并发控制**：按用户限制上下行带宽与并发连接数；


## 快速开始

从 [Releases](https://github.com/hhy50/vnray/releases) 下载对应平台的 `vnserver`（服务端）与 `vnclient`（客户端），并从仓库 [`configs/`](configs/) 目录获取示例配置。

### 1. 启动服务端

示例配置 [`configs/server.yaml`](configs/server.yaml) 默认：`9000` 客户端隧道、`8080` 管理台（账号 `admin/admin`）、`bindings.db`（SQLite）。

```bash
./vnserver -c configs/server.yaml
```

首次启动会自动初始化数据库，并插入一把范围为 `default:*` 的初始密钥 `2nC7NBBcutpkJg0cPkyQgkzXqtWrri/JB4QyXI5N258=`（与示例客户端配置一致）。生产环境请在管理台重新生成密钥。

### 2. 启动客户端

在能访问目标服务的机器上，编辑 [`configs/client.yaml`](configs/client.yaml) 后启动：

```yaml
server:
  addr: <服务端公网地址>:9000
  auth_key: 2nC7NBBcutpkJg0cPkyQgkzXqtWrri/JB4QyXI5N258=
group: default        # 分组，留空用 default
name: desktop-01      # 组内实例名，留空生成 <hostname>-<IPv4>
```

```bash
./vnclient -c configs/client.yaml
```

客户端保持长连接，断线自动重连。

### 3. 打开管理台创建用户

访问 `http://<服务端地址>:8080`：

1. **客户端**页确认客户端在线；
2. **插件**页启用入站协议并设置监听端口；
3. **用户**页创建用户，选择协议与出口客户端，复制连接信息导入 v2ray / ss 客户端；
4. 需要暴露内网 TCP 服务时，在**端口映射**页创建映射。

OpenWrt 可使用 [`openwrt/`](openwrt/README.md) 的客户端插件（LuCI 配置页、开机自启、多架构打包）。

## 端口与协议

| 用途 | 默认 / 配置位置 | 说明 |
| --- | --- | --- |
| 客户端隧道 | `9000`（`server.listen`） | 客户端主动连接，不承载用户协议 |
| vnray-user 用户入站 | 插件页配置（如 `9001`） | `vn-v1` 用户的独立端口，默认停用 |
| 管理台 | `8080`（`admin.listen`） | 管理客户端、用户、插件、端口映射 |
| VMess / VLESS / SS 入站 | 管理台插件页配置 | 供标准客户端连接 |

## 配置文件与命令行

- [`configs/server.yaml`](configs/server.yaml)：监听、认证、管理台、存储、插件、日志；
- [`configs/client.yaml`](configs/client.yaml)：连接地址、认证密钥、重连、访问控制、路由。

```text
-c, --config  配置文件路径（YAML）；不传时使用内置默认值
```

客户端可用 `--server <地址>:9000` 临时覆盖服务端地址。

## 场景选择

- 多个用户用标准客户端接入 → 创建 VLESS / VMess / SS 用户；
- 只暴露一个内网 TCP 服务 → 用端口映射（如内网 SSH 映射到公网端口）；
- 让流量从指定网络的出口发出 → 创建用户并绑定对应客户端。

## 安全提示

示例配置仅用于本地验证（默认管理台账号、公开的初始密钥）。暴露到公网前至少完成：

- 修改管理台账号密码；
- 生成新密钥并按客户端 / 分组设置授权范围，删除初始密钥；
- 只开放实际需要的端口，限制管理台访问来源；
- 为用户设置合理的带宽、并发与客户端访问范围；
- 生产环境优先启用 VLESS TLS，妥善保管证书与密钥。
